# kead

Personal operating system app — deployed to [kaed.hu](https://kaed.hu).

Next.js 15 (App Router) + React 19 + Tailwind v4, backed by Supabase (Postgres + auth). Deploys to Vercel from `main` on every push.

## Structure

- `app/` — pages (Server Components) and API routes (`app/api/**`, Route Handlers)
- `lib/` — framework-agnostic data access, types, and business logic per feature; `lib/auth.ts` + `lib/supabase.ts` are the auth/DB entry points
- `components/` — shared client UI: the design-system class strings (`ui.tsx`), inline-edit cells, popups, nav
- `supabase/schema.sql` — source of truth for the database, not auto-applied (see `CLAUDE.md`)
- `middleware.ts` — refreshes the Supabase session on every request

## Conventions

- Pages are `async` Server Components; run independent Supabase queries with `Promise.all`, never one `await` at a time.
- Mutations are Route Handlers. Default style: a plain `<form method="post">` that the handler answers with a 303 redirect (`?error=…` back to the page on failure). For interactions that must not re-run the page, a client component `fetch`es a JSON handler — `InlineEdit` for click-to-edit cells, and `app/business-ideas/IdeaList.tsx` for optimistic delete/reorder.
- Inline-edit endpoints are generated by `createFieldRoute` (`lib/field-route.ts`) from a table name + field spec.
- Styling is Tailwind utilities composed from `components/ui.tsx`; `app/globals.css` holds design tokens only, no component classes.

## Local development

```sh
cp .env.example .env   # fill in real values
npm install
npm run dev             # http://localhost:4321
```

| Command | Action |
| :-- | :-- |
| `npm run dev` | Start the dev server |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run typecheck` | `tsc --noEmit` |

See `CLAUDE.md` for the full working conventions (auth helpers, mutation patterns, Supabase migrations, the finance module's derived-value rules).
